# palimp

You inherit a Juniper SRX with a few hundred security policies, and nobody
left can tell you why most of them exist. palimp is an open-source, offline
command line tool that reconstructs that lost intent from what you find on and
around the firewall: the configuration, the commit history and rollback files,
session logs, hit counts, and optional ticket or CMDB exports. For each rule it
gives a probable intent, the ranked evidence behind it, a confidence level, a
verdict (keep, verify, removal candidate) and the one question to ask the rule
owner. Existing tools tell you what a rule does or what is wrong with a
ruleset; palimp tells you why a rule is there. Nothing leaves your machine.

## What a report looks like

An excerpt of the report `palimp demo` writes, on a synthetic scenario (a
fictional company generated by palimp's simulator, no real network or person):

> #### R24 `users/dc/app-lms-web-01`
>
> - **What it allows:** Allows local-nets (group of 3), in zone users, to reach WWW02 (10.20.29.11/32), in zone dc, for HTTPS (tcp/443). [E2] [E7]
> - **Why palimp asks:** V-NO-TRAFFIC-SEEN: no traffic seen, which does not prove the policy is unused (rare job, cleared counters). [E5] [E6]
>   - hitcount.txt, policy app-lms-web-01 (users -> dc): 0 hits since the counters were last cleared (the clear date is not in hitcount.txt) [E5]
>   - logs/rt_flow.log, policy-name="app-lms-web-01": the policy logs session-close, and no session was logged in the log window 2025-07-26 to 2025-09-23 (60 days); a job that runs less often than every 60 days would not show in it [E6]
> - **Intent:** Probably for lms, MEDIUM confidence: direct evidence names an application, the address objects do not confirm it. Stated purpose, a claim palimp does not check: the description says "ansible role fw-lms v5" (E1). [E1]
> - **Who to ask:** Elif Kowal, application owner (requester of 2 of 2 tickets for lms [E4]).
> - **Question:** Is this flow still needed, even if it runs rarely? (yes / no)

Every claim cites an evidence item (`[E5]`), and the report opens with what
palimp is sure of, what it is not sure of, and what it could not see.

## Install

palimp needs Python 3.12 or later. With [pipx](https://pipx.pypa.io/):

    pipx install palimp

From a clone of this repository: `pipx install .` (or `uv sync` and
`uv run palimp` for development).

## Quickstart

    palimp demo                                  # bundled synthetic scenario, report in a new temp directory
    palimp report -a ARTIFACTS -o OUT            # OUT/report.md, OUT/report.json, firewall team cleanup list
    palimp explain users/dc/app-lms-web-01 -a ARTIFACTS   # one policy (FROM/TO/NAME), or --all
    palimp questions -a ARTIFACTS -o OUT         # one email per person, cleanup list, OUT/answers.csv
    palimp ingest ARTIFACTS -o data.json         # the normalized model, reusable with -a data.json
    palimp anonymize -a ARTIFACTS -o COPY --key KEYFILE   # a copy safe to share, see Privacy

`palimp demo --out DIR` writes the demo to a directory of your choice
(`DIR/artifacts` holds the synthetic input, so you can rerun any command on
it).

## What palimp reads

Put the files in one directory (ARTIFACTS):

    config.set                 show configuration (hierarchical or | display set)
    rollbacks/rollback-NN.set  show system rollback NN (either format), NN = commit index
    commits.txt                show system commit
    hitcount.txt               show security policies hit-count
    logs/rt_flow.log           RT_FLOW session logs (syslog)
    tickets.csv                optional ticket or CMDB export

Only `config.set` is required; every other file adds evidence, and the
report says which ones were missing. The configuration format is detected per
file: the hierarchical output of `show configuration` and the set output of
`show configuration | display set` give the same analysis, and a saved
terminal session (prompts, `[edit]` banners) is accepted. Prefer the
hierarchical output: Juniper documents annotations (`/* ... */` notes added
with `annotate`) in it, and palimp uses them as evidence.

Zone policies and global policies (`security policies global`, shown as
`global/NAME`) are read. A deactivated zone pair, `policies` or `security`
block deactivates every policy under it, as Junos does at commit.

Evidence is ranked in four tiers: direct statements (a commit comment, a
policy description or annotation, a ticket reference), behavior (session
logs, hit counts), structure (object names, zones, rules created in the same
commit) and context (well-known ports). Confidence comes from which tiers are
present and whether they agree; a rule backed only by context never goes
above LOW.

## Evaluation

palimp is scored against a synthetic company simulator that writes a
realistic firewall history together with a ground truth file (the true intent
and status of every rule). The simulator and the analyzer share no code, and
the sessions that tune the analyzer never read the simulator. Full history:
[docs/evaluation-history.md](https://github.com/n-le-bourdiec/palimp/blob/main/docs/evaluation-history.md).

Dev scenarios, simulator 0.5.1 (tuning used other seeds, 0 to 19):

| metric | Medium, seeds 20-99 (12840 rules) | Hard, seeds 20-49 (12671 rules) |
|---|---|---|
| verdict equals the best the artifacts allow | 91.7% | 98.1% |
| removal candidate on a live or still needed rule (palimp) | 0 | 0 |
| same, naive baseline | 191 | 148 |
| intent right vs best achievable | 82.1% | 78.6% |
| intent right vs true application | 59.2% | 51.3% |
| HIGH confidence: intent right | 96.7% | 95.6% |
| overconfident (above what the artifacts justify) | 3.3% | 2.1% |
| underconfident | 13.1% | 11.1% |

The naive baseline keeps a rule with hits (or with no hit count file) and
proposes removal of every other rule; it is how a cleanup by hit
counts alone goes, and each of its errors would cut a flow someone still
needs. "Intent vs best achievable" compares palimp with the best intent the
given artifacts allow, while "vs true application" compares it with the
application the simulator knows the rule serves; they differ because many
rules carry no trace of their application at all (a generic name, a history
older than the retained commits), and no tool can recover what the files do
not hold.

50, Hard 30, seeds derived from a secret salt) run once per release, by the
project lead only, in GitHub Actions. Their numbers will replace this

## What palimp does not do

- It never connects to a device and never writes a command meant to be
  pushed. Reports, questionnaires and lists are for people to read.
- It does not decide for you. A removal candidate needs a positive sign that
  the rule is not in use (deactivated, decommissioned application, migration
  leftover whose old servers are silent), never missing traffic alone, and
  you still confirm with the person named.
- It does not judge whether a rule is too broad or compliant, and it does not
  analyze NAT, routing or rule order beyond rules after a catch-all deny of
  their zone pair.
- Other vendors, live connections, configuration changes and a web UI are out
  of scope for v1.

## What palimp could not see

Every report has a section with this title, listing the blind spots of the
artifacts you gave (log window, history horizon, policies without logging,
counter clears, missing files). Read it before acting on any verdict. Some
limits hold for every run:

- Scanner and monitoring traffic on a policy that does not log looks like
  business use: hit counts say that sessions matched, not who opened them or
  whether a server answered. palimp recognizes probe traffic only in session
  logs.
- A renamed application, or an address that now serves another application,
  is detected only when an artifact ties the new application to the rule.
- With the configuration alone there is no traffic and no history: every
  intent rests on names, descriptions and annotations, confidence stays LOW
  or MEDIUM, and no rule is a removal candidate unless it is deactivated.
- `apply-groups` is reported but not expanded (`show configuration | display
  inheritance` prints inherited policies in place); tenant and logical system
  policies are not read.

## Known limits

- palimp has never been run on a real SRX history. It has been tested on
  synthetic scenarios, with Junos output formats confirmed by samples from
  Juniper's documentation and by published practitioner captures
  ([docs/format-assumptions.md](https://github.com/n-le-bourdiec/palimp/blob/main/docs/format-assumptions.md)).
- Real configurations were tested with the configuration alone: 32 configs
  published on GitHub (292 policies), no crash, every policy found
  ([docs/real-configs-robustness.md](https://github.com/n-le-bourdiec/palimp/blob/main/docs/real-configs-robustness.md)).
  No real commit history, log or hit count file has been read.
- The ground truth is synthetic. The simulator encodes one model of how
  firewalls drift; the numbers above measure palimp against that model, not
  against your network.

If something looks wrong on a real firewall, please open an issue with an
anonymized copy (below).

## Privacy

- Fully offline: no network egress, no telemetry, no update check. The
  optional LLM must be a local Ollama server (localhost or a loopback address
  only).
- To share artifacts in an issue, make an anonymized copy first:

      palimp anonymize -a ARTIFACTS -o shared-copy --key ~/palimp.key --strip-text

  It replaces IP addresses (private stay private, one subnet stays one
  subnet), policy, object, application and zone names, people, logins, host
  names, ticket IDs, and every known name inside free text, the same way in
  every file, so palimp analyzes the copy as it analyzes the original. Keep
  the key private and outside the copy. `--strip-text` removes free text
  (descriptions, annotations, commit comments, ticket summaries) instead of
  rewriting it: recommended for a bug report, at the cost of that evidence.
  `--shift-dates` moves every date back by a secret number of whole weeks.
- What the copy still reveals: this is keyed pseudonymization, not
  encryption. The structure stays (number of rules, zones, which rule allows
  what, subnet layout), as do ports, protocols, Junos predefined
  applications, the signal words palimp reads (`temp`, `decom`, `CHG`, ...),
  name lengths and shared prefixes, weekdays and times of day, and, without
  `--strip-text`, any word of free text palimp does not know as a name (a
  person mentioned only in a comment). Read the copy before you post it.

## The LLM writer (experimental, off by default)

`--llm --llm-model MODEL` (on `explain` and `report`) adds a prose paragraph
per rule written by a local Ollama server. The LLM writes, it never judges:
every sentence must cite evidence and state only facts found in it, or it is
replaced by the deterministic text; artifact text is passed as untrusted data.

It is off by default because it was measured and found not worth it yet: on
a 4 GB laptop GPU, the best small model (qwen3.5:4b) wrote 58% of the rule
paragraphs without a rejected sentence, about 8% of the sentences that passed
the checks were still misleading (true facts wrongly related, which the
checks cannot see), its paragraphs often left out the intent, confidence and
verdict reason, and a 170-rule report went from 2 seconds to 26 minutes.
Verdicts, confidence and owners never depend on it. Details:
[docs/llm-writer-measure.md](https://github.com/n-le-bourdiec/palimp/blob/main/docs/llm-writer-measure.md).

## How this was built

palimp was written by an AI coding agent (Claude Code), directed and
challenged by the project lead. Each session had one mission stated in its
prompt and started from the project memory in the repository
(`CLAUDE.md`, `HANDOFF.md`); every significant choice is a decision record in
[docs/decisions/](https://github.com/n-le-bourdiec/palimp/tree/main/docs/decisions),
with the project lead's challenges and their outcome. Sessions 1 to 34 took
3,313 model calls, at an API-equivalent cost of 235.10 USD (token counts at
list prices, not a billed amount), computed from
[metrics/sessions.csv](https://github.com/n-le-bourdiec/palimp/blob/main/metrics/sessions.csv)
in [metrics/summary.md](https://github.com/n-le-bourdiec/palimp/blob/main/metrics/summary.md).
